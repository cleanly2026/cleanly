## Color

Source: `packages/config/tailwind.config.ts` — established in Phase 1. Confirmed by globals.css.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#F8F7F4` (`brand.surface`) | Admin panel page background, main content area |
| Secondary (30%) | `#1A2744` (`brand.navy`) | Fixed sidebar background, table header row, modal overlay |
| Accent (10%) | `#C9A84C` (`brand.gold`) | Primary action buttons only (see reserved list below) |
| Destructive | `#DC2626` (`semantic.destructive`) | Reject company button, issue refund button, delete actions |
| Success | `#16A34A` (`semantic.success`) | Approved/verified status badges, payout confirmed indicator |
| Warning | `#D97706` (`semantic.warning`) | Pending review status badges, open dispute indicator |
| Muted | `#E8E5DF` (`brand.muted`) | Skeleton loaders, disabled states, table dividers |

Accent (`brand.gold`) reserved for:
1. "Approve Company" primary button on company review page
2. "Save Changes" button on city/category CRUD pages
3. Focused form field ring (2px ring on active inputs)
4. Active sidebar navigation item indicator (left border or background highlight)

Accent is NOT used for: status badges, table row hover states, icons, secondary actions, cancel/close buttons, or any destructive flow.

Sidebar text color: white (`#FFFFFF`) on `brand.navy` background. Sidebar active item: `brand.gold` left border (4px) + semi-transparent gold tint background.

## RTL / Bilingual Contract

All admin-web pages use the `[locale]` routing already established. Apply these rules:

| Element | LTR | RTL (Arabic) |
|---------|-----|--------------|
| Sidebar position | Left | Right (CSS logical: `inset-inline-start: 0`) |
| Sidebar item text align | Left | Right |
| Table column order | Left-to-right | Mirrored |
| Back link arrow | ← | → |
| Stat card number alignment | Left | Right |
| Form field text direction | LTR (AED amounts, emails, phone) | RTL for Arabic text inputs |

Phone number inputs and currency inputs always render LTR regardless of locale (`dir="ltr"` on those input elements specifically — established pattern from Phase 1 OtpInput).

Admin panel English-only strings are acceptable for private beta (D-14 permits rough edges on admin panel). However, all Next.js pages must still use the `[locale]` routing pattern and `useTranslations()` hook — hardcode English translation keys for now; Arabic translation keys can be filled in post-beta.

## States Contract

Every data-fetching surface must implement all three states:

| State | Implementation |
|-------|---------------|
| Loading | Skeleton loaders using `brand.muted` (#E8E5DF) fill — match the shape of the loaded content (table rows: 6 skeleton rows; stat cards: 4 skeleton cards) |
| Empty | Centered illustration-free empty state: heading (Heading size, semibold) + body copy (Body size, regular, muted text) |
| Error | Inline error banner below page title: `semantic.destructive` left border (4px), error message, retry button |

Error boundary: each admin page wrapped in a React error boundary that catches render errors and displays: "Something went wrong loading this page. [Refresh]" without crashing the sidebar.

## Interaction Contracts

### Approval / Rejection Flow

1. Admin clicks "Approve Company" → optimistic status badge update to "Approved" → API call → on success: toast "Company approved" + emit admin socket event → on failure: revert badge + inline error banner.
2. Admin clicks "Reject with Reason" → RejectReasonModal opens → admin fills reason (required) → "Confirm Rejection" button → API call → modal closes → status badge updates to "Rejected" → on failure: modal stays open + inline error inside modal.

### Refund Flow

1. "Issue Refund" button opens RefundModal (not a page navigation).
2. Admin selects full or partial refund.
3. If partial: amount field validates ≤ order total; shows real-time remaining balance below field.
4. Reason field required; "Confirm Refund" button disabled until reason ≥ 10 characters.
5. On submit: button shows spinner, disabled; API call; on success: modal closes, dispute status updates to "Resolved", audit log entry created; on failure: error shown inside modal, button re-enabled.

### Destructive Confirmation Pattern

All destructive actions (reject company, issue refund, delete city, delete category) follow this pattern:
- First click → modal/sheet opens with clear destructive consequence statement.
- Confirm button uses `semantic.destructive` fill color.
- Cancel always available and closes without any action.
- No double-confirm ("type the name to delete") — too slow for admin ops at this scale.

### Data Table Interactions

- Row click → navigate to detail page.
- Status filter → query param update → table re-fetches with filter.
- All tables: 10 rows per page default, pagination controls at bottom.
- Column sort: click column header to toggle asc/desc; active sort column shows arrow icon.

### Dispute Photo Viewer

- Photos load from R2 signed URLs (15-minute TTL, generated server-side on page load).
- If photo URL fails to load: show placeholder with camera icon + "Photo unavailable" label.
- Click photo → opens in lightbox (full screen) with close button.
- On mobile: photos stacked vertically, each full width; tap to expand lightbox.

## Implementation Notes for Executor

1. Admin sidebar is a server component layout in `apps/admin-web/app/[locale]/layout.tsx` — add sidebar wrapper there so it appears on all admin feature pages without per-page import.
2. All admin API routes protected by existing admin auth middleware from Phase 1 (`authenticate` preHandler checking `role === 'admin'`).
3. Follow the existing `[locale]` + `useTranslations()` pattern from customer-web — admin-web already has this routing. English-only translation keys are acceptable for private beta.
4. `packages/ui` exports shared components — add any reusable admin components there only if they will also be used in customer-web. Admin-specific components (sidebar, stat cards, dispute viewer) live in `apps/admin-web/src/components/`.
5. All currency amounts displayed as "AED {amount}" with 2 decimal places. Never use "$" or other currency symbols.
6. Timestamps displayed using `next-intl`'s `useFormatter().dateTime()` — never format dates manually.
