Two client apps (customer-web and company-web) construct API URLs without /api prefix. After Task 1 adds /api to server routes, these clients will 404 unless updated. The fix uses a base-URL strategy: append /api to each app's API base constant so all relative paths resolve correctly.

**customer-web/src/lib/api.ts** (line 1):
Change:
  const API_BASE = process.env.NEXT_PUBLIC_API_URL || 'http://localhost:3000'
To:
  const API_BASE = (process.env.NEXT_PUBLIC_API_URL || 'http://localhost:3000') + '/api'

This automatically fixes ALL apiFetch callers across customer-web:
- /cities -> /api/cities
- /companies/* -> /api/companies/*
- /orders/* -> /api/orders/*
- /customer/orders/* -> /api/customer/orders/*

**customer-web/src/components/dispute-reason-sheet.tsx** (line 31):
Change path from '/api/disputes' to '/disputes' because the base URL now includes /api.
The call `apiFetch('/api/disputes', ...)` would become /api/api/disputes (double prefix) without this fix.

**customer-web/src/lib/auth-client.ts** (lines 5 and 27):
This file constructs fetch URLs directly with API_URL (separate from api.ts base).
