# Phase 3 — UI Design Contract

> Visual and interaction contract for Phase 3: Real-Time & Washer App.
> Generated by gsd-ui-researcher. Verified by gsd-ui-checker.

This phase spans two Expo React Native surfaces: `apps/washer-mobile` (washer-facing) and `apps/customer-mobile` (customer GPS tracking screens). Both surfaces use the same brand token system established in Phase 1. No shadcn/components.json — components are custom React Native primitives following existing patterns in `packages/ui`.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | Custom (no shadcn) — tokens in `packages/config/tailwind.config.ts`, mirrored as StyleSheet constants for RN |
| Preset | not applicable |
| Component library | Custom primitives in `packages/ui/src/` (web-only); Phase 3 adds RN-specific primitives under `apps/washer-mobile/src/components/` and `apps/customer-mobile/src/components/` |
| Icon library | Lucide React Native (consistent with Lucide React on web surfaces) |
| Font | Cairo — loaded via `expo-font` with `useFonts` hook; system-ui fallback. Same token as web: `fontFamily: ['var(--font-cairo)', 'system-ui', 'sans-serif']` expressed as `{ fontFamily: 'Cairo' }` in RN |
| Map library | `react-native-maps` with Google Maps provider on Android, Apple Maps on iOS (Claude's discretion — pre-existing expo-location for GPS is a natural pairing) |

**Source:** Design token values pre-populated from `packages/config/tailwind.config.ts` and `apps/customer-web/app/globals.css`. No new tokens introduced in Phase 3.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, badge inner padding, chip gap |
| sm | 8px | Compact list item gap, button icon gap, inline element spacing |
| md | 16px | Default screen padding (horizontal), card inner padding, form field gap |
| lg | 24px | Section spacing, card outer margin, bottom sheet internal padding |
| xl | 32px | Layout gaps between major screen sections |
| 2xl | 48px | Major section breaks, top hero area spacing |
| 3xl | 64px | Page-level top padding on full-screen overlays |

**Exceptions (Phase 3 specific):**
- All interactive touch targets minimum 44px height — enforced via `minHeight: 44` on all Touchable elements. Applies to: Accept/Decline buttons, checklist checkboxes, photo upload tap areas, online/offline toggle.
- Job alert Accept button: 56px height — primary action on full-screen takeover, requires prominent tap affordance.
- Job alert Decline button: 44px height — minimum touch target, visually subordinate to Accept.
- Countdown ring container: 120px diameter — large enough to read at arm's length in bright outdoor light.
- Map view (customer tracking screen): fills available screen height minus header (approximately 60% of viewport). No fixed pixel height — use `flex: 1` within a flex container.
- Status card (in_progress, service active): fixed 180px height card overlaying bottom of screen — shows washer name + elapsed time + service type.
- Bottom safe area: all screens apply `paddingBottom: safeAreaInsets.bottom` via `useSafeAreaInsets()`. Minimum 16px bottom padding even when safe area inset is 0.

## Typography

All font sizes mirrored from the shared Tailwind config into React Native StyleSheet constants. Cairo loaded via `expo-font`.

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Label | 14px | 400 (regular) | 1.4 | Metadata, earnings sub-labels, checklist item descriptors, ETA text, photo upload status text |
| Body | 16px | 400 (regular) | 1.5 | Service type, address text, job details, customer notes, checklist item text |
| Heading | 20px | 600 (semibold) | 1.3 | Job alert service name, screen section titles, washer home card headings |
| Display | 28px | 600 (semibold) | 1.2 | Job alert countdown number, today's earnings total, job completion confirmation |

**Weights used:** regular (400) and semibold (600) only. No medium, bold, or light variants — consistent with all prior phases.

**Font:** Cairo for all text on both mobile surfaces. RTL: `I18nManager.forceRTL(true)` + `writingDirection: 'rtl'` on root view for Arabic mode (established pattern from Phase 1).

**Monospace exception:** Order numbers (e.g., `CLN-00123`), AED amounts displayed in earnings totals — use system monospace (`fontFamily: 'monospace'`) for column alignment. Source: Phase 2 UI-SPEC monospace exception.

## Screens and Component Inventory

### Washer Mobile (`apps/washer-mobile`)

#### Screen 1 — Home / Dashboard (WASH-01, D-10)
- Full-screen scrollable. Background: `brand.surface`.
- **Online/offline toggle:** Large pill toggle at top of screen. "Online" state: gold fill, dark text. "Offline" state: muted fill, navy text. Toggle is 56px height, full-width. Below toggle: status label "You are online — waiting for jobs" or "You are offline".
- **Earnings card:** Navy background card. Today's earnings: display-size, gold monospace text. Jobs completed today: label, white text. Card padding: `lg` (24px). Border radius: 12px.
- **Next scheduled job card** (shown only if a job is assigned and upcoming): Body-size service type, heading-size ETA time, label-size address. Gold "Navigate" button — 44px height.
- **Jobs completed list** (below cards): compact list of today's completed jobs. Each row: order number (mono, label), service type (body), amount earned (mono, label). Divider lines using `brand.muted`.
- Empty state (no jobs today): illustration area + "No jobs completed today" (heading) + "Go online to start receiving assignments." (body). No illustration defined yet — executor uses a placeholder.

#### Screen 2 — Job Alert — Full-Screen Takeover (WASH-02, ORD-04, D-01, D-02)
- Covers full screen including status bar area. Background: `brand.navy`.
- **Header:** "New Job" label (label, white, centered) at top. Dismiss is not available — accept or decline only.
- **Countdown ring:** 120px diameter circular progress arc. Arc color: `brand.gold`. Background track: 20% opacity white. Center: countdown number (display-size, semibold, white). Ring counts down 30 → 0 seconds. When <10s: arc color switches to `semantic.warning`.
- **Service details block:** Service type icon (32px) + service name (heading, white). Company name (body, white 70% opacity). Customer address (body, white 70% opacity). Estimated distance (label, white 60% opacity).
- **Map preview:** Small embedded map (180px height) showing customer pin and approximate washer position. Navy-tinted overlay at 30% opacity. No interaction — view only.
- **Buttons:** Two full-width buttons, stacked. Top: Accept (56px, gold background, navy semibold text, "Accept Job"). Bottom: Decline (44px, transparent background, `semantic.destructive` border + text, "Decline").
- **Timer expiry:** If 30s passes without action — screen auto-dismisses, toast appears: "Job auto-declined — you've been set to offline."

#### Screen 3 — En Route (WASH-03, RT-01, D-02)
- Map fills top ~60% of screen (flex: 1 in upper container). Google Maps provider. Shows route polyline from washer to customer. Customer pin: navy fill. Washer pin: animated pulsing dot (brand-gold).
- **Bottom sheet (persistent, 40% height):** `brand.surface` background, rounded top corners (16px radius). Contents: customer name + service type (heading). ETA countdown (display, gold). Address (body). "Navigate" button: full-width, 44px, gold background, navy text, Google Maps deep-link. "I've Arrived" secondary button: full-width, 44px, navy background, white text. "Call Customer" icon button: 44px, muted background, navy icon — tel: deep-link.

#### Screen 4 — Before Photo Upload (PHO-01, PHO-03, D-07, D-08, D-09)
- Screen background: `brand.surface`.
- Instruction text: heading "Take a before photo" (PHO-01) or "Photograph carpets for pickup" (PHO-03). Body: "Show the vehicle/sofa/carpets in full view before cleaning begins."
- **Camera launch button:** Full-width, 56px, gold background, navy text, camera icon (20px) + "Open Camera". Launches native system camera via `expo-image-picker`.
- **Photo review area:** After taking photo — thumbnail (full-width, 200px height, border-radius 8px). Below thumbnail: "Upload Photo" button (gold, 44px) + "Retake" link (body size, navy).
- **Upload progress:** Linear progress bar below button. Gold fill on muted track. Label: "Uploading… X%". On complete: success checkmark icon (`semantic.success`) + "Photo saved".
- **Skip option:** "Skip for now" link (label size, `semantic.warning` color) at bottom. Tapping opens a 2-option bottom sheet: "Poor signal — will upload later" / "No photo needed" with a confirmation button. Source: D-09.

- **Checklist (WASH-05):** Single scrollable page. Section heading: "Service Checklist" (heading, navy). Per category, checklist items listed. Each item: checkbox (44px touch target) + item text (body). Checked item: navy checkmark, text color dims to muted. Unchecked: empty square, full-opacity navy text.

## Interaction Contracts

### Job Alert Countdown Timer (WASH-02, ORD-04, D-01, D-03)
- `setInterval` at 1000ms updates countdown display from 30 to 0.
- Ring arc re-renders on each tick: `(remaining / 30) * 360` degrees, drawn as SVG arc or via `react-native-svg` `Circle` with `strokeDashoffset`.
- At 0: auto-decline fires, order reassigns via API, washer status set to offline via `PATCH /api/washers/status { online: false }`.
- Washer is NOT shown a confirmation dialog on auto-decline — it happens immediately. A toast appears after dismissal: "Job auto-declined — you're now offline."
- Haptic feedback on Accept tap: `Haptics.notificationAsync(Haptics.NotificationFeedbackType.Success)` via `expo-haptics`.
- Haptic feedback on Decline tap: `Haptics.impactAsync(Haptics.ImpactFeedbackStyle.Medium)`.

### GPS Tracking Broadcast (RT-01, RT-04, WASH-04)
- `expo-location` `watchPositionAsync` with `accuracy: Location.Accuracy.High` and `timeInterval: 5000` (5s), `distanceInterval: 10` (meters).
- On each position update: emit `washer:location` Socket.io event with `{ orderId, lat, lng, heading }`.
- Android Foreground Service: `expo-task-manager` with `defineTask(LOCATION_TASK_NAME)`. Task registered in `app.json` under `plugins`. Foreground service notification: "Cleanly — job in progress" (title) + "Location sharing active" (body). Icon: app icon.
- Redis cache: API route handler for `washer:location` event writes to `washer:location:{washerId}` key with 30s TTL. Source: RT-05.
- Customer map receives `order:washer_location` Socket.io event and smoothly animates the washer marker to the new coordinates using `Animated` API with 800ms duration.

### Photo Upload Flow (PHO-05, PHO-06, D-07, D-08)
- Presigned URL obtained from `GET /api/photos/upload-url?orderId={id}&photoType={type}` — returns R2 presigned URL with 60s TTL. Source: Phase 1 r2.ts scaffold.
- Upload: `fetch(presignedUrl, { method: 'PUT', body: imageFile, headers: { 'Content-Type': 'image/jpeg' } })`.
- Retry: on `fetch` failure, exponential backoff: 2s → 4s → 8s, max 3 retries. After 3 failures: show "Upload failed — tap to retry" banner. Background retry loop continues silently (does not block job progression).
- Photo compression: `expo-image-manipulator` — resize to max 1200px on longest side, JPEG quality 0.8 before upload. Source: D-08.
- `photoType` values: `before` (PHO-01), `after` (PHO-02), `pickup` (PHO-03), `return` (PHO-04). Matches `buildPhotoKey` pattern from Phase 1: `orders/{orderId}/{photoType}/{timestamp}.jpg`.

### Online/Offline Toggle (WASH-01)
- Toggling to "Offline" while on an active job: show confirmation bottom sheet. Heading: "Go Offline?" Body: "You have an active job. Going offline won't cancel it, but you won't receive new jobs until you go back online." CTA: "Go Offline" (`semantic.destructive` style), "Stay Online" (gold style).
- Toggling to "Online": immediate, no confirmation. API: `PATCH /api/washers/status { online: true }`.
- Toggle state persists across app restart via AsyncStorage (same pattern as language preference in Phase 1).

### Checklist Completion Gate (WASH-05, WASH-06, D-11, D-12)
- "Complete Job" button enabled only when ≥80% of checklist items are checked.
- If washer taps "Complete Job" with <80% checked: inline warning text appears below button (not a toast): "Please complete at least X more checklist items before finishing." (`semantic.warning`, label size).
- On complete: API `PATCH /api/orders/{id}/status { status: 'completed' }`. On success: navigate to job completion confirmation.

### ETA Calculation (D-04, RT-02)
- Simple estimate only (Claude's discretion — no Google Distance Matrix API in Phase 3 per v2 deferral of ENH-03).
- Formula: `etaMinutes = Math.round(distanceMeters / 8.33)` (assuming 30km/h average urban speed, 8.33 m/s).
- Distance: Haversine formula between washer lat/lng and customer lat/lng. Recalculates on each GPS update.
- Displayed as "Arriving in ~X min". If <2min: "Arriving now".

### Map Direction Handling (I18N-06)
- Map labels switch to Arabic when AR mode active: pass `language: 'ar'` to `MapView` `mapType` prop or via Google Maps URL parameter (react-native-maps supports `customMapStyle` with localized labels).
- Map interaction (pan/zoom): not localized — no directional changes needed for maps.
- Bottom sheet text: RTL layout when Arabic active (`I18nManager.isRTL`). Use `flexDirection: 'row-reverse'` on horizontal containers.

### Loading and Skeleton States
- Washer home earnings card: skeleton (navy background, shimmer over earnings amount + job count) while data loads.
- Customer tracking bottom sheet: skeleton (washer avatar circle + 2 text line skeletons) while Socket.io connection establishes.
- No circular spinners — skeletons only. Shimmer animation: left-to-right gradient, 1.2s loop. Source: Phase 2 convention.

## RTL / Bilingual Contracts

All Phase 3 components follow the RTL rules established in Phase 1 and carried through Phase 2:

1. Use `marginStart`/`marginEnd` (not `marginLeft`/`marginRight`) throughout all React Native StyleSheet definitions. Source: CLAUDE.md + Phase 1 decision.
2. Use `paddingStart`/`paddingEnd` (not `paddingLeft`/`paddingRight`) for horizontal padding.

5. Map: direction-neutral. Map component itself does not mirror. Source: Phase 2 RTL contract, Map pin exception.
6. Countdown ring: SVG arc direction — always clockwise regardless of locale. Clock direction is not a cultural UI element.
7. Checklist items: text and checkbox layout use `flexDirection: row` (reversed in RTL). Checkboxes appear on the right in Arabic (trailing side).
8. Arabic ETA and amount formatting: use `Intl.NumberFormat('ar-AE', { style: 'currency', currency: 'AED' })` for currency display. Elapsed time: Arabic-Indic numerals via `toLocaleString('ar')`.
9. `dir=ltr` exception from Phase 1 (numeric-only inputs): applies to order number display (monospace), earnings amount, phone numbers. Wrap these in a `View` with `direction: 'ltr'` style.
