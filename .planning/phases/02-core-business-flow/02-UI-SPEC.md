## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, chip inner padding, badge padding |
| sm | 8px | Compact element spacing, button icon gap, list item gap |
| md | 16px | Default element spacing, form field gap, card inner padding |
| lg | 24px | Section padding, card outer margin, modal padding |
| xl | 32px | Layout gaps, content section spacing |
| 2xl | 48px | Major section breaks, page-level vertical rhythm |
| 3xl | 64px | Top-level page padding, hero section gap |

**Exceptions:**
- Touch targets on interactive controls (add-on chips, washer assignment dropdown): minimum 44px height — use `min-h-[44px]` with `py-sm` to achieve this.
- Sticky bottom bar (booking summary): fixed height 72px to accommodate price text + CTA button within safe area insets.
- Status filter tabs on company order feed: 40px height (dense UI, data-heavy context).

## Typography

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Label | 14px | 400 (regular) | 1.4 | Form labels, badge text, metadata, price breakdowns, tab labels |
| Body | 16px | 400 (regular) | 1.5 | Company descriptions, package descriptions, review text, address notes |
| Heading | 20px | 600 (semibold) | 1.3 | Section titles, company name on profile page, modal titles, package names |
| Display | 28px | 600 (semibold) | 1.2 | Service category screen headline, booking confirmation headline, order status headline |

**Weights used:** regular (400) and semibold (600) only. No medium, bold, or light variants.

**Font:** Cairo for all text on customer-web (`apps/customer-web`). Cairo for company-web dashboard (`apps/company-web`) — same token, consistent cross-surface.

**RTL note:** Cairo renders correctly in both LTR (English) and RTL (Arabic) modes. `dir` attribute on `<html>` controls layout direction; no font override needed.

**Monospace exception:** Order numbers (e.g., `#ORD-00123`), amounts in fils formatted as AED values, timestamps in company dashboard table — use `font-mono` (system default monospace stack) to preserve column alignment in the data table.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#F8F7F4` (`brand-surface`) | Page backgrounds, screen backgrounds for customer-web and company-web |
| Secondary (30%) | `#1A2744` (`brand-navy`) | Service category cards, company listing cards, company profile header, company dashboard sidebar/nav, modal overlays |
| Accent (10%) | `#C9A84C` (`brand-gold`) | See accent list below |
| Muted | `#E8E5DF` (`brand-muted`) | Skeleton loaders, disabled add-on chips, divider lines, empty state backgrounds |
| Destructive | `#DC2626` (`semantic-destructive`) | Cancel order CTA, delete package/add-on CTA, payment failure inline error text |
| Success | `#16A34A` (`semantic-success`) | Order confirmed state badge, payment success indicator, "Stripe Connect connected" badge |
| Warning | `#D97706` (`semantic-warning`) | Pending order badge, carpet order "in_cleaning" and "ready_for_return" state badges |

**Accent (`brand-gold`) reserved for these specific elements only:**
1. Primary CTA buttons ("Book Now", "Confirm & Pay", "Assign Washer", "Save Package")
2. Focus rings on all interactive inputs and buttons
3. Active state on service category cards (selected border)
4. Active filter tab indicator underline on company order feed
5. Star rating icons (filled stars only — empty stars use `brand-muted`)
6. Running total price in sticky bottom booking bar

Accent is NOT used for: headings, body text, card backgrounds, dividers, nav items, badges, or any decorative element not in the list above.

## Screens and Component Inventory

### Customer Web (`apps/customer-web`)

#### Screen 1 — Home / Service Category Selection (DISC-01)
- 3 category cards, full-width on mobile, 2-up on tablet. Each card: category illustration, category name (heading weight), brief descriptor (label weight).
- Selected card: `brand-gold` border (2px solid), `brand-navy` background with white text.
- Unselected card: `brand-surface` background, `brand-navy` text, `brand-muted` border.
- City display badge at top of screen: city name + GPS icon. Tappable — opens city picker sheet (DISC-02).
- **City picker sheet:** Bottom sheet (mobile) / modal (desktop). Scrollable list of available cities. Selected city highlighted with accent checkmark.

#### Screen 2 — Company Listing (DISC-03, DISC-04)
- Single-column scrollable list. Each card: company logo (48px circle avatar), company name (heading), star rating + review count (label), response time badge (label), starting price (body). Card background: white. Outer margin: `lg`.
- No results state: illustrated empty state — see Copywriting Contract.
- Loading state: 3 skeleton cards matching exact card dimensions.

#### Screen 3 — Company Profile (DISC-05)
- Single scroll page. Sections in order:
  1. Header: company logo, name, rating summary, response time, city/categories.
  2. Packages: each package as a card — name (heading), description (body), price (body semibold). Select button uses accent CTA style.
  3. Add-ons: toggleable chips. Selected chip: `brand-navy` fill, white text. Unselected chip: `brand-muted` fill, navy text. Minimum 44px height.
  4. Reviews: show 3 most recent. Each: reviewer avatar (32px), name (label semibold), star rating, review body (body). "See all reviews" link — body size, navy color, no accent.

#### Screen 4 — Booking Screen, On-Site (BOOK-01–04)
- Single scrollable page. Sticky bottom bar: 72px height, `brand-navy` background, gold price total (label semibold), "Book Now" CTA button (accent fill, white text, 44px height).
- Section order: package summary → add-ons → location pin → access notes → order summary.
- Location section: full-width map view (240px height on mobile), draggable centered pin, reverse-geocoded address below map (body), parking notes text input below address.
- Order summary: itemized list — package name + price, each add-on + price, service fee, total. All amounts in "AED X.XX" format. Divider between subtotal and fee. Total row: semibold.

#### Screen 5 — Booking Screen, Carpet (CARP-01–04)
- Same sticky bar and scroll structure as on-site booking.
- Replaces location section with: date picker for pickup slot (CARP-02), 2-hour time slot grid (9-11, 11-1, 1-3, 3-5 — grid of chips, single-select).
- Estimated return date shown as label below time slot grid: "Estimated return: {date}".
- Carpet count input: numeric stepper (minus button, count, plus button) — 44px touch targets.

#### Screen 6 — Payment (PAY-01, PAY-03, PAY-04)
- Stripe Payment Element embedded inline below the order summary. Full-width. Do not wrap in a card — Stripe's own styling handles the container.
- "Confirm & Pay AED X.XX" CTA button: full-width, accent fill, 52px height (larger for payment confidence).
- Payment failure: inline error text below the Stripe element. `semantic-destructive` color. Body size. No modal, no toast — inline only (D-11).
- Service fee line: label "Service fee (15%)" with label-weight price. Standard marketplace pattern (D-10).

#### Screen 7 — Booking Confirmed (ORD-01)
- Centered layout. Display-size order confirmation heading. Order number in monospace label. Service summary (body). "View Order" link.
- Background: `brand-surface`. No card container — full-page confirmation treatment.

#### Screen 8 — Order Status / Tracking (ORD-01–06)
- Status progress indicator: horizontal step dots for 7-state (on-site) or 10-state (carpet) lifecycle. Active step: `brand-gold`. Completed steps: `brand-navy`. Upcoming: `brand-muted`.
- Current status badge: pill shape, color-coded by state (see semantic colors above).
- Cancellation: "Cancel Order" link at bottom of screen — `semantic-destructive` color, body size. Requires confirmation (see Copywriting Contract).

### Company Web (`apps/company-web`)

#### Screen 9 — Order Feed Dashboard (COMP-05, COMP-06)
- Full-width data table. Status filter tabs across top: All / Pending / Active / Completed. Active tab: `brand-gold` underline indicator, semibold label. Inactive tab: regular label, `brand-muted` underline.
- Table columns: Order # (mono), Customer, Service, Status badge, Time, Amount (mono), Actions.
- Status badges: pill shape. Pending = `semantic-warning` bg. Active = `brand-navy` bg white text. Completed = `semantic-success` bg. Cancelled = `semantic-destructive` bg.
- Washer assignment cell: "Assign" link → inline dropdown of available washers → "Confirm" button. Do not navigate away from the table (D-14).
- Real-time row updates: new order rows animate in with a 300ms fade-in from top of the relevant filter section.

#### Screen 10 — Company Onboarding (COMP-01–04, COMP-07)
- Multi-step flow: Profile → Services → Packages → Stripe Connect. Step indicator at top (4 dots or labeled steps).
- Bilingual fields: each text input has an EN / AR tab toggle above it. Both must be filled before proceeding.
- City coverage: multi-select checkboxes for available cities.
- Stripe Connect section: "Connect Stripe Account" CTA button → opens Stripe Connect OAuth in new tab. After return: success badge showing connected account.

#### Screen 11 — Package & Add-On Management (COMP-03)
- Two-panel layout: package list (left) + add-on list (right) on desktop. Single-column stacked on mobile.
- Add/edit uses inline form expansion (not navigation) — click "Add Package" → form slides open below the list.
- Delete: trash icon button → inline confirmation text "Delete this package? This cannot be undone." + "Delete" (`semantic-destructive`) and "Cancel" buttons. No modal.

#### Screen 12 — Washer Staff Management (COMP-04)
- Simple table: Name, Phone, Status (active/inactive), Actions (edit, deactivate).
- "Add Washer" button: accent CTA, top-right of the table header.

## Interaction Contracts

### Sticky Bottom Bar (Booking Screens)
- Always visible, never scrolls away.
- Price updates instantly when add-ons are toggled (no loading state, pure client state).
- On mobile: bottom safe area inset applied (`pb-safe` or `env(safe-area-inset-bottom)`).
- "Book Now" button disabled (muted state) until required fields are complete: package selected + location pinned (on-site) or pickup slot selected (carpet).

### Map Pin Location (BOOK-03)
- Map renders at 240px height on mobile, 360px on desktop.
- Centered pin is always centered in the map container — user drags the map, not the pin.
- On drag end: reverse geocode fires, address text updates below map.
- If GPS unavailable: map centers on city center coordinates for the customer's selected city.

### Add-On Chips (BOOK-02, DISC-05)
- Toggle: tap chip to select/deselect. Immediate visual feedback (no debounce).
- Selected chip: `brand-navy` fill, white label, checkmark icon at left (16px).
- Price appended to chip label: "+ AED 15" in label-size.

### Order State Machine Display (ORD-01, CARP-05)
- Progress dots update in real time via Socket.io (Phase 2 scaffolds the display; GPS dot is Phase 3).
- State change: active dot animates with a 200ms pulse before settling.
- Cancelled state: all dots go to `semantic-destructive`, progress bar shows red.

### Company Order Feed Real-Time (COMP-05)
- New orders appear at the top of the "Pending" tab with a 300ms slide-in + highlight flash (`brand-gold` background at 20% opacity, fading to `brand-surface` over 1s).
- Order status updates in the active row — status badge swaps with a 150ms crossfade.

### Form Validation (All Forms)
- Validation triggers on blur (not on every keystroke).
- Error text: `semantic-destructive`, label size, positioned directly below the input.
- Success state (on blur, field passes validation): no icon, no color change — silence is success.
- Required bilingual fields: if the AR field is empty on submit, error text reads the AR translation of the error (not English).

### Loading States
- Company listing: 3 skeleton cards matching exact card dimensions (logo circle, 2 text lines, price line). Shimmer animation: left-to-right gradient, 1.2s loop.
- Company profile: skeleton for header + 2 skeleton package cards before data loads.
- Order feed table: 5 skeleton rows.
- No circular spinner anywhere — skeletons only (per taste-design anti-patterns).

## RTL / Bilingual Contracts

All new Phase 2 components MUST follow these rules (carried forward from Phase 1 decisions):

1. Use CSS logical properties throughout: `ms-`, `me-`, `ps-`, `pe-`, `border-s`, `border-e`. Never `ml-`, `mr-`, `pl-`, `pr-`, `border-l`, `border-r`.
2. Map pin is direction-neutral — no mirroring needed.
3. Stripe Payment Element: renders in Arabic automatically when locale is set. Pass `locale: 'ar'` to Stripe's `Elements` component when Arabic mode is active.
4. Order state progress indicator: step dots flow right-to-left in RTL. Use `flex-row-reverse` on the step container when `dir="rtl"`.
5. Data table (company dashboard): column order reverses in RTL. Table headers and cells use `text-start` (not `text-left`).
6. Booking sticky bar: price on the trailing side, CTA button on the leading side in RTL.
7. `dir=ltr` exception from Phase 1 (OtpInput/PinInput containers) applies to any numeric-only inputs (carpet count stepper, phone numbers).
