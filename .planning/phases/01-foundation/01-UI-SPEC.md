# Phase 1 — UI Design Contract

> Visual and interaction contract for Phase 1: Foundation.
> Generated by gsd-ui-researcher. Consumed by gsd-planner, gsd-executor, gsd-ui-auditor.

---

## Phase Scope (UI)

Phase 1 is primarily infrastructure but delivers the FIRST user-facing screens:
authentication flows for all 4 roles. These screens establish every visual and
interaction pattern that all subsequent phases inherit.

**User-facing outputs of this phase:**
1. Customer phone OTP entry and verification screen
2. Washer phone OTP + 4-digit PIN screen
3. Company admin email + password + TOTP MFA screen
4. Platform admin Google SSO screen (redirect only — minimal UI)
5. Language switcher (AR/EN toggle) — persisted to profile
6. Bilingual RTL layout shell (the root `<html dir>` contract)

**NOT in this phase:** Booking, discovery, payments, tracking — those are Phase 2+.

### Cairo Font Integration

Per I18N-05 and the verified pattern from CONTEXT7_VERIFIED.md:

```typescript
// apps/customer-web/app/[locale]/layout.tsx
import { Cairo } from 'next/font/google'

const cairo = Cairo({
  subsets: ['arabic', 'latin'],
  display: 'swap',
  variable: '--font-cairo',
})

export default function RootLayout({ children, params: { locale } }) {
  const dir = locale === 'ar' ? 'rtl' : 'ltr'
  return (
    <html lang={locale} dir={dir} className={cairo.variable}>
      <body>{children}</body>
    </html>
  )
}
```

- `display: 'swap'` is mandatory (I18N-05: zero CLS requirement)
- Set `--font-cairo` as CSS variable; apply in Tailwind config: `fontFamily: { cairo: ['var(--font-cairo)'] }`
- In Arabic mode (`dir="rtl"`), `font-family: var(--font-cairo)` applies to ALL text
- In English mode (`dir="ltr"`), fall back to Inter/system-ui for body text; Cairo still available for headings if desired

## RTL / Bilingual Layout Contract

This is the most critical contract in Phase 1. ALL subsequent phases inherit these rules.

### CSS Property Rules (enforced project-wide)

| Avoid | Use Instead | Reason |
|-------|-------------|--------|
| `margin-left` / `margin-right` | `margin-inline-start` / `margin-inline-end` | Flips automatically in RTL |
| `padding-left` / `padding-right` | `padding-inline-start` / `padding-inline-end` | Flips automatically in RTL |
| `left` / `right` (positioning) | `inset-inline-start` / `inset-inline-end` | Flips automatically in RTL |
| `text-align: left` | `text-align: start` | Flips automatically in RTL |
| `ml-*` / `mr-*` (Tailwind) | `ms-*` / `me-*` (Tailwind logical) | Tailwind v4 logical property classes |
| `pl-*` / `pr-*` (Tailwind) | `ps-*` / `pe-*` (Tailwind logical) | Tailwind v4 logical property classes |

Exceptions: Icons that have inherent directionality (e.g., back-arrow) MUST be flipped with `[dir="rtl"] .icon-directional { transform: scaleX(-1) }`.

### Language Switching Contract

- Language toggle is visible on ALL auth screens (top-right corner in LTR, top-left corner in RTL)
- Toggle label: English mode shows "العربية", Arabic mode shows "English"
- On switch: `<html dir>` attribute changes immediately without page reload
- Preference persisted: localStorage pre-auth, profile column (`preferred_language`) post-auth (I18N-04)
- Font switches: `dir="ar"` activates Cairo font via CSS variable swap

### String Externalization

- Zero hardcoded strings in any component (I18N-01)
- All strings in `packages/i18n/locales/{en,ar}.json`
- Keys follow dot-notation: `auth.otp.title`, `auth.otp.resend_cta`, `auth.pin.placeholder`
- Arabic strings reviewed by native speaker before Phase 1 ships (quality gate — not automated)

## Spacing Scale

Declared values (multiples of 4, 8-point base):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, OTP digit separator, badge padding |
| sm | 8px | Input label-to-field gap, helper text margin |
| md | 16px | Default element spacing, input internal padding |
| lg | 24px | Section padding, card internal padding |
| xl | 32px | Between form groups, card-to-card gap |
| 2xl | 48px | Auth card vertical padding |
| 3xl | 64px | Page-level vertical centering offset |

Exceptions:
- OTP digit boxes: 48px × 56px minimum touch target (WCAG 2.5.5 enhanced — Gulf mobile users expect large touch targets)
- PIN digit boxes: same 48px × 56px minimum
- Language toggle button: 44px minimum height (WCAG 2.5.5 AA)
- All interactive elements: 44px minimum touch target (WCAG 2.5.5 AA)

## Typography

| Role | Size | Weight | Line Height | Font | Notes |
|------|------|--------|-------------|------|-------|
| Body | 16px | 400 (regular) | 1.5 | Cairo (AR) / Inter (EN) | Input helper text, terms copy |
| Label | 14px | 500 (medium) | 1.4 | Cairo (AR) / Inter (EN) | Form field labels, nav items |
| Heading | 20px | 600 (semibold) | 1.3 | Cairo (AR) / Inter (EN) | Auth screen titles |
| Display | 28px | 700 (bold) | 1.2 | Cairo (AR) / Inter (EN) | App name / brand lockup on auth screens |

Rules:
- Exactly 4 sizes: 14, 16, 20, 28
- Exactly 2 weights for body content: 400 + 600 (500 for labels only, not body)
- Arabic text at same px sizes — Cairo renders slightly larger optically; no size compensation
- No italic in Arabic (poor rendering for most Arabic fonts including Cairo)
- Minimum body size: 16px on mobile (never scale below 16px to prevent iOS zoom-on-focus)

## Color

The ROFAN brand targets a premium, trustworthy feeling for Gulf customers. The palette is
**deep navy + warm white + gold accent** — conveying cleanliness, reliability, and premium positioning.

| Role | Hex | HSL (Tailwind CSS var) | Usage |
|------|-----|----------------------|-------|
| Dominant (60%) | `#F8F7F4` | `40 20% 97%` | Page backgrounds, auth screen surface |
| Secondary (30%) | `#1A2744` | `222 44% 18%` | Auth card background, nav, sidebar |
| Accent (10%) | `#C9A84C` | `42 55% 55%` | See reserved-for list below |
| Destructive | `#DC2626` | `0 72% 51%` | Error states, invalid OTP, failed auth |

Accent (`#C9A84C` — warm gold) reserved exclusively for:
1. Primary CTA buttons (Send Code, Verify, Sign In, Continue with Google)
2. Active/focus ring on OTP and PIN digit input boxes
3. Language toggle active indicator underline
4. Brand wordmark accent element (if used on auth screens)

**NOT** used for: body text, borders, backgrounds, disabled states, informational badges.

Semantic colors:
- Success: `#16A34A` (green-600) — OTP verified indicator, session established toast
- Warning: `#D97706` (amber-600) — OTP expiry countdown when < 30s remaining
- Muted surface: `#E8E5DF` — disabled input backgrounds, skeleton loaders

Dark mode: Phase 1 does NOT implement dark mode. The secondary color (`#1A2744`) is used as
the card background to provide contrast depth — this is NOT a dark mode, it is the brand identity.

## Interaction Contracts

### OTP Input Behavior

- Auto-advance: focus moves to next box when a digit is entered
- Auto-retreat: backspace on empty box moves focus to previous box
- Paste: pasting "123456" fills all 6 boxes and auto-submits if complete
- RTL Arabic mode: digit boxes remain LTR order (digits are always LTR in all languages)
- Invalid state: all boxes shake (Motion Primitives shake animation, 300ms) + red border
- Expiry: countdown timer from 60s; at 0, "Resend" link activates; boxes disabled during cooldown

### OTP Resend Rate Limiting

- AUTH-07: 3 OTP sends per phone per 15 minutes (enforced server-side)
- Client shows: "Too many attempts. Try again in X minutes." after 3rd attempt
- Timer shown: remaining cooldown period

### Form Validation

- Phone number: validated client-side (UAE format: 05X-XXX-XXXX) before API call
- Email: standard HTML5 email validation + server-side bcrypt check
- TOTP: 6-digit numeric only; auto-submit on 6th digit
- PIN: 4-digit numeric only; auto-submit on 4th digit; masked display

### Loading States

- Button shows `<Loader2 className="animate-spin" />` icon during API call (from Lucide)
- Skeleton overlays replace OTP boxes during initial SMS send (300ms min display)
- No optimistic UI — wait for server confirmation before advancing screen

### Error States

| Error | Display |
|-------|---------|
| Invalid OTP code | All 6 boxes shake (Motion) + red border + toast: "Incorrect code. X attempts remaining." |
| OTP expired | Toast: "Code expired. Tap Resend to get a new code." + boxes cleared |
| Rate limited | Toast: "Too many attempts. Try again in 15 minutes." + boxes + button disabled |
| Network error | Toast: "Connection error. Check your internet and try again." |
| Invalid phone format | Inline field error below phone input (no toast) |
| Wrong email/password | Toast: "Incorrect email or password." (never specify which field for security) |
| MFA required | Advance to TOTP screen automatically (not an error — expected flow) |
| Invalid TOTP | Shake + toast: "Incorrect code. Try again." |

## Tailwind CSS v4 RTL Configuration

In `packages/ui-components/tailwind.config.ts`, ensure:

```typescript
export default {
  content: ['./src/**/*.{ts,tsx}'],
  theme: {
    extend: {
      colors: {
        brand: {
          surface:    '#F8F7F4',  // dominant 60%
          navy:       '#1A2744',  // secondary 30%
          gold:       '#C9A84C',  // accent 10%
          muted:      '#E8E5DF',  // disabled surfaces
        },
        semantic: {
          success:     '#16A34A',
          warning:     '#D97706',
          destructive: '#DC2626',
        },
      },
      fontFamily: {
        cairo: ['var(--font-cairo)', 'system-ui', 'sans-serif'],
      },
      fontSize: {
        'label': ['14px', { lineHeight: '1.4' }],
        'body':  ['16px', { lineHeight: '1.5' }],
        'heading': ['20px', { lineHeight: '1.3' }],
        'display': ['28px', { lineHeight: '1.2' }],
      },
    },
  },
}
```

CSS logical properties are Tailwind v4 native (`ms-*`, `me-*`, `ps-*`, `pe-*`).
No plugin required. Use them instead of `ml-*`/`mr-*`/`pl-*`/`pr-*` everywhere.
