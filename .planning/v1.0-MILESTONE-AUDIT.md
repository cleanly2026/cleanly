## Cross-Phase Integration

**Connected:** 48 exports/APIs properly wired | **Broken:** 5 connections | **Orphaned:** 1 dead queue

### BLOCKER 1: Washer Status Transition Calls Route 404

**Phase 3 → Phase 2 | Affects: WASH-06, ORD-01, PAY-04, NOTF-01-04**

`en-route.tsx` and `complete.tsx` in washer-mobile call `PATCH ${API_URL}/api/orders/${orderId}/status`. But `server.ts` registers `orderLifecycleRoutes` at prefix `/orders` (not `/api/orders`). The endpoint lives at `/orders/:id/status`. Both washer calls return **404 at runtime**.

**Impact:** Washer can never transition order to `in_progress` or `completed`. Payout job never enqueued. Completion notifications never fire.

**Fix:** Either re-register lifecycle routes under `/api/orders` or change washer-mobile fetch calls from `/api/orders/:id/status` to `/orders/:id/status`.

### BLOCKER 2: Washer Job Alert Never Delivered (3 Sub-Failures)

**Phase 2 → Phase 3 | Affects: WASH-02, ORD-03, ORD-04**

**A.** `lifecycle.ts` assign-washer handler never emits `job:alert` to `washer:{userId}` room. Only emits `order:status-changed` to company/order rooms and enqueues push notification.

**B.** `handleJobAlert` in `index.tsx` is a commented-out stub — navigation to `/(job)/alert` never happens.

**C.** `useWasherSocket.acceptJob` emits `job:accept` socket event — server has no handler for it. `socket.ts` only handles `join:company`, `join:order`, `washer:join-order`, `washer:location`, `washer:leave-order`.

**Impact:** Company assigns washer → washer gets push → opens app → nothing happens. Entire washer dispatch loop non-functional.

### BLOCKER 3: Company Dashboard Real-Time Events Never Received

**Phase 2 internal | Affects: ORD-02, COMP-05, COMP-06**

`useOrderSocket` emits `socket.emit('join', 'company:${companyId}')` — event name is `'join'`. Server handles `socket.on('join:company', ...)`. Room `company:{companyId}` is **never joined**. All `order:new` and `order:status-changed` events are lost.

**Fix:** Change `useOrderSocket.ts` from `emit('join', ...)` to `emit('join:company', { companyId, token })`.

### Additional Findings

4. **Company-web has no route guard (AUTH-03, AUTH-04, COMP-05):** SPA routes `/orders`, `/packages`, `/washers` accessible without authentication. No `PrivateRoute` or redirect to login page.

5. **Dead `order-lifecycle` queue** in `queues/queues.ts` — Queue named `'order-lifecycle'` with no matching worker. Real queue is `'orders'` in `lib/queue.ts`. Wastes Redis connection but no functional impact.

## Broken E2E Flows

### Flow 1: On-Site Order Lifecycle (Washer Path) — BROKEN

```
Customer books → Company accepts → Company assigns washer → Washer receives alert
  [BREAK: job:alert never emitted] → Washer accepts [BREAK: handleJobAlert stub] →
  En route [BREAK: job:accept dropped] → Arrives [BREAK: PATCH 404] →
  Active → Completes [BREAK: PATCH 404] → Payout [never queued]
```

**Working steps:** Customer booking, payment, company order feed (manual refresh), company assigns washer, push notification to washer device.
**Broken steps:** In-app alert delivery, accept/decline, arrival transition, completion transition, payout trigger, completion notifications.

### Flow 2: Real-Time Company Dashboard — BROKEN

```
New order created → API emits order:new to company:{companyId} →
  [BREAK: company never joined room] → Dashboard never receives event
```

**Working steps:** API emits event correctly to correct room.
**Broken steps:** company-web client emits `'join'` instead of `'join:company'` — event lost.

### Flow 3: Washer Job Alert Dispatch — BROKEN

All three layers broken simultaneously:
- Server never emits `job:alert` to washer room
- Client `handleJobAlert` is a commented-out stub
- `job:accept`/`job:decline` socket events have no server handlers
