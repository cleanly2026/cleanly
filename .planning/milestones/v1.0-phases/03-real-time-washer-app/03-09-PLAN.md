<objective>
Wire photo URLs from socket events through to customer tracking screen.

Purpose: Root cause 4 from VERIFICATION.md. The server correctly emits `order:photo-uploaded` with `{ photoType, photoUrl }` when washers upload photos. The `useOrderTracking` hook listens for this event but ignores the data (no-op handler). The tracking screen has photo state variables (`beforePhotoUrl`, `afterPhotoUrl`) but they are never populated. This plan wires the socket event data through the hook into the screen.

Output: Customer sees before/after photos in real-time as the washer uploads them during a live order.
</objective>

   ```typescript
   socket.on('order:photo-uploaded', (data: { photoType: string; photoUrl: string }) => {
     setState(s => {
       if (data.photoType === 'before' || data.photoType === 'pickup') {
         return { ...s, beforePhotoUrl: data.photoUrl }
       }
       if (data.photoType === 'after' || data.photoType === 'return') {
         return { ...s, afterPhotoUrl: data.photoUrl }
       }
       return s
     })
   })
   ```
   Note: `pickup` maps to `beforePhotoUrl` and `return` maps to `afterPhotoUrl` because for carpet orders, the pickup photo is the "before" equivalent and the return photo is the "after" equivalent.
